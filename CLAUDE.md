# CLAUDE.md

Faust I (Spanish, Llorente) as a Ren'Py visual novel. This repo is a *work*: the pipeline
(`vnpipe`) lives in its own repo (`../vnpipe`, git dependency on its `development` branch, pinned by `uv.lock`).

## Rules
- Repo content in English; the game text is Spanish (from the source, never rewritten).
- Pipeline code, schemas, prompts and GUI templates belong in `../vnpipe`, not here.
  Anything specific to this text goes in `work.toml`.
- `vn/` is generated by `vnpipe renpy`; never edit it by hand.
- Every stage must be deterministic and idempotent; LLM/image outputs are cached by input hash.
- ChatGPT image MCP: max 20 generations per hour.
- Voice: `voice/asr/*.json` (GPU ASR cache) and `voice/clips/*.ogg` are committed; only the raw
  mp3s and German text are gitignored. Never put voice clips under `audio/` (they would become music moods).

## Commands
- `export UV_CACHE_DIR=$TMPDIR/uv-cache` first when running inside the sandbox.
- `uv sync` — install. `uv run pytest` — tests. `uv run ruff check . && uv run ruff format --check .` — lint.
- To test against an unmerged vnpipe worktree: `uv run --with-editable <vnpipe worktree> pytest -q`
  (and `--project <vnpipe worktree> vnpipe --work . parse` to run a stage).
- `uv run vnpipe --help` — pipeline CLI (the work is the repo root). Stages: `fetch`, `parse`,
  `annotate {run,status,prompt,merge}`, `assets {...}`, `voice {fetch,asr,build,cut}` (`docs/voice.md`),
  `translate {fetch,build,status}` (English, Taylor; `data/translations/en.json`), `renpy [--with-test --out DIR]`.
- Ren'Py SDK lives in `tools/renpy-sdk` (gitignored; may be a symlink shared between worktrees)
  or `RENPY_SDK`. Inside the sandbox prefix SDK commands with `HOME=$TMPDIR/renpy-home`.
  Lint: `tools/renpy-sdk/renpy.sh vn lint`. Playthrough test and builds: `docs/running.md`.
- vnpipe comes from git (pinned in `uv.lock`); after pushing vnpipe changes run
  `uv lock --upgrade-package vnpipe`. Unpushed vnpipe: `uv run --with-editable ../vnpipe <cmd>`.

## Branches and versions
- `development` is the integration branch; `main` receives reviewed merges from it.
  Feature work branches off `development` (`feat/...`, `fix/...`).
- `VERSION` is bumped by `.github/workflows/version.yml` on push (patch on `development`,
  minor on a `development` -> `main` merge). Do not edit it by hand.
- CI (`.github/workflows/ci.yml`) runs ruff and pytest; vnpipe is public and fetched over HTTPS.
- `main` is the remote's default branch; `development` is only for ongoing work.
- Remote is GitHub `Dasemu/faust-vn` (SSH push needed for workflow changes, see `LESSONS.md`).
  `.github/workflows/release.yml` builds win/linux/mac/web/APK and publishes a release per
  new version on `main`; the APK keystore is the `ANDROID_KEYSTORE_B64` secret (`docs/running.md`).

## Layout
`work.toml`, `data/`, `annotations/`, `assets/`, `voice/`, `vn/`, `tests/`, `docs/`; see `docs/plan.md`.
